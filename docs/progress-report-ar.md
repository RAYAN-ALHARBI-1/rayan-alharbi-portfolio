# تقرير متابعة الموقع الشخصي

**آخر تحديث:** 3 نوفمبر 2026

## جاهز الآن

### الواجهة

- موقع عام داكن موحد يعرض الصورة الشخصية والخبرة والمشاريع والشهادات.
- الصفحة العامة تجلب الملف الشخصي والمشاريع والشهادات المنشورة من واجهة الخادم عند توفر قاعدة البيانات، مع إبقاء المحتوى الثابت كنسخة احتياطية عند عدم توفرها.
- ملفات شهادات الروبوتات قابلة للفتح من الموقع.
- صفحة مستقلة لدخول الإدارة ولوحة لإدارة الملف الشخصي والمشاريع والشهادات.
- لوحة الإدارة تدعم إضافة المشاريع والشهادات وتعديلها وحذفها بعد تأكيد واضح.
- هيدر الموقع على الجوال ثابت، وقائمة التنقل تظهر فوق المحتوى لتبقى قابلة للاختيار أثناء التصفح.

### الخادم

- خادم ASP.NET Core 10 يعمل محليًا ويقدّم صفحات الموقع.
- فحوصات صحة: `/health` و`/health/live`.
- واجهة عامة: `GET /api/v1/portfolio`.
- واجهات إدارة محمية للملف الشخصي والمشاريع والشهادات، بما فيها الإنشاء والتعديل والحذف للمشاريع والشهادات.
- ترحيل قاعدة بيانات PostgreSQL أول جاهز في `src/Portfolio.Server/Data/Migrations`.
- سكربت إعداد سحابي ينفذ الترحيلات ويضيف المحتوى الأولي دون حفظ رابط الاتصال داخل المشروع.

### الحماية

- Google OAuth من جهة الخادم، لا تحقق شكلي في المتصفح.
- Cookie من نوع HttpOnly وSameSite=Strict لجلسة الإدارة.
- رمز CSRF لعمليات الحفظ والخروج.
- السماح بحسابات إدارة محددة فقط مع دورَي `owner` و`editor`.
- رؤوس حماية وحدّ لمحاولات الوصول إلى الواجهات الحساسة.

## ما ينتظر إعداد الحسابات

1. إنشاء قاعدة PostgreSQL سحابية وتشغيل `scripts/connect-cloud-database.ps1` مرة واحدة.
2. إنشاء Google OAuth Client وإضافة Client ID وClient Secret وعناوين البريد المصرح بها.
4. اختيار تخزين خاص للصور وملفات PDF.
5. إضافة مفتاح Gemini API وبناء مسار تحليل الشهادات على الخادم فقط.
6. اختيار الاستضافة وربط اسم نطاق قبل النشر العام.

## غير منفذ عمدًا

- لا يوجد رفع ملفات فعلي إلى مجلد عام أو جهاز محلي.
- لا يوجد تحليل AI دون مفتاح مخزن خارج Git.
- لا يوجد نشر أو قاعدة بيانات تجريبية عامة قبل حسم مزود الاستضافة.
- لم تُدفع التعديلات الجديدة إلى GitHub بعد.

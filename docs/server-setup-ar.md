# إعداد خادم الموقع الشخصي

## الحالة

الخادم مبني بـ ASP.NET Core 10 ويعمل دون قاعدة بيانات لعرض الموقع العام وفحوصات الصحة. عند عدم ضبط قاعدة البيانات، يعيد المسار `/api/v1/portfolio` رسالة واضحة بحالة `503` بدل إعطاء بيانات وهمية.

## قاعدة البيانات

المزود المختار حاليًا هو PostgreSQL. يحتوي المشروع على ترحيلات EF Core؛ لذلك لا تنشئ الجداول يدويًا في الإنتاج.

### تطوير محلي

بعد إنشاء قاعدة PostgreSQL سحابية، استخدم السكربت التالي من جذر المشروع:

```powershell
.\scripts\connect-cloud-database.ps1
```

السكربت يحفظ الرابط في User Secrets فقط، ثم ينفذ الترحيلات ويضيف البيانات الأولية إذا لم تكن موجودة. التفاصيل في `docs/cloud-database-ar.md`.

### إنتاج

ضع رابط الاتصال في إعدادات منصة الاستضافة باسم:

```text
ConnectionStrings__PortfolioDb
```

ثم شغّل الترحيلات من مرحلة نشر موثوقة. لا تضع الرابط داخل `appsettings.json` أو JavaScript أو Git.

## دخول الإدارة

الخادم لا يسمح بأي حساب لمجرد أنه سجل الدخول إلى Google. يجب أن يكون البريد موجودًا في قائمة `AdminAccess:AllowedEmails`، ويمنح دور المالك إذا كان موجودًا في `AdminAccess:OwnerEmails`.

عنوان العودة المحلي المطلوب في Google Cloud Console:

```text
http://127.0.0.1:5088/signin-google
```

عند النشر، أضف عنوان العودة بالنطاق الحقيقي وبـ HTTPS فقط.

## رفع الملفات لاحقًا

المسار الصحيح هو:

1. المستخدم المصرح له يرفع ملفًا بصيغة وحجم مسموحين.
2. الخادم يتحقق من الحجم، النوع، ومحتوى الملف.
3. الخادم يخزنه في Object Storage خاص.
4. قاعدة البيانات تحفظ بيانات الملف فقط، وليس مسارًا مكشوفًا أو مفتاح تخزين.
5. الخادم يصدر رابط عرض أو تحميل مؤقتًا بعد التحقق من الصلاحية.

لا يجب أن يرفع المتصفح مباشرة إلى مجلد عام أو يحصل على مفاتيح التخزين.

## Gemini لاحقًا

يُرسل الخادم نصًا مستخرجًا من شهادة عامة إلى Gemini ويعيد اقتراحات قابلة للتعديل. لا يحفظ الناتج ولا ينشره قبل ضغط المستخدم على الحفظ. لا يوضع مفتاح Gemini في الواجهة أو Git.
